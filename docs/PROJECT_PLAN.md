# PROJECT_PLAN — BookConnect

## 1. Основна цел
BookConnect е уеб приложение за управление на училищна библиотека. То ще позволява търсене, проверка на наличности, заемане, връщане и резервиране на книги.

## 2. Основни функционалности
1. Регистрация и вход — потребителите ще влизат със собствен акаунт.
2. Каталог — показване на книги със заглавие, автор, жанр и описание.
3. Търсене и филтриране — по заглавие, автор и жанр.
4. Проверка на наличност — показване на свободните екземпляри.
5. Заемане — библиотекарят ще записва кой е заел определен екземпляр.
6. Връщане — библиотекарят ще отбелязва върнатите книги.
7. Резервации — потребителите ще заявяват книги, които искат да заемат.
8. Известия — съобщение при налична резервирана книга.
9. Администрация — библиотекарят ще добавя, редактира и премахва книги.
10. Проследяване на срокове — списък на активните и просрочените заемания.

## 3. Потребителски истории
- Като ученик искам да търся книга по заглавие, за да я намеря бързо.
- Като ученик искам да виждам наличността, за да знам дали мога да я заема.
- Като ученик искам да резервирам книга, за да изчакам свободен екземпляр.
- Като библиотекар искам да записвам заеманията, за да следя кой държи книгите.
- Като библиотекар искам да отбелязвам връщанията, за да актуализирам наличностите.
- Като учител искам да филтрирам книгите по жанр, за да намирам подходяща литература.

## 4. Собствен алгоритъм — опашка за резервации
Цел: когато се освободи екземпляр, да се определи кой потребител трябва да получи предимство.

Входни данни:
- Идентификатор на книгата.
- Списък от чакащи резервации с дата и час.
- Брой свободни екземпляри.

Обработка:
1. Намираме активните резервации за книгата.
2. Подреждаме ги по дата и час на заявяване.
3. При еднакво време използваме уникален идентификатор за еднозначен ред.
4. Ако има свободен екземпляр, избираме първата резервация.
5. Отбелязваме резервацията като готова за получаване.
6. Предотвратяваме повторно разпределяне на същия екземпляр чрез проверка и транзакция в базата данни.

Резултат: идентификатор на следващата резервация или съобщение, че няма чакащи или свободен екземпляр.

Псевдокод:

    function nextReservation(bookId, reservations, availableCopies):
        if availableCopies == 0:
            return null
        waiting = filter reservations where book_id == bookId and status == 'waiting'
        sort waiting by created_at ascending, id ascending
        if waiting is empty:
            return null
        return waiting[0]

Гранични случаи:
- Няма чакащи резервации.
- Няма свободни екземпляри.
- Двама потребители са резервирали едновременно.
- Една и съща книга има няколко екземпляра.

Примери за ръчна проверка:
1. Има един екземпляр и две резервации от 10:00 и 11:00 — избира се тази от 10:00.
2. Няма свободни екземпляри — не се избира резервация.
3. Има свободен екземпляр, но няма чакащи — резултатът е null.

Сложност: O(n log n) за сортиране на n резервации. При реалното заемане ще е необходима атомарна операция в базата данни, за да не се заеме един екземпляр два пъти.

## 5. Технологии
- HTML5 — структура на страниците.
- CSS3 — оформление и адаптивен дизайн.
- JavaScript ES6+ — търсене, филтриране, проверки и взаимодействие с потребителя.
- Supabase PostgreSQL — съхранение на книги, потребители, заемания и резервации.
- Supabase Auth — регистрация и вход.
- Supabase RLS — ограничаване на достъпа според потребителските права.
- Git и GitHub — съхранение на кода, история на промените и екипна работа.
- GitHub Pages — публикуване на началния интерфейс.
- Vitest — автоматизирано тестване на JavaScript алгоритмите, ако бъде включен в реализацията.

Не планираме външен API на първия етап.

## 6. Планирана база данни
- profiles — потребители и роли.
- books — информация за заглавията.
- genres — жанрове.
- copies — отделни физически екземпляри.
- loans — заемания и връщания.
- reservations — заявки за резервация.
