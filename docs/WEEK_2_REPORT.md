# WEEK 2 REPORT — BookConnect

**Проект:** BookConnect — Уеб система за управление на училищна библиотека  
**Клас:** 10.  
**Екип:** Борис Димов и Габриела Нешева  
**Етап:** 2 — начални екрани, реална база и JavaScript

## 1. Цели

- Реализиране на два адаптивни и свързани уеб екрана.
- Минимум три свързани таблици в Supabase и тестови записи.
- JavaScript за четене на данни, търсене, филтриране и подготвен защитен запис.
- BG/EN езиков превключвател.
- Изходен код, проектна документация и отчет в GitHub.

## 2. Реално извършени дейности

1. Реализиран е `index.html`: начален екран и каталог, търсене по заглавие и автор, жанр, наличност, модален прозорец за детайли, BG/EN.
2. Създаден е `librarian.html` — втори екран с таблица за наличности, броячи, BG/EN, форма за вход на библиотекар.
3. `script.js` зарежда от Supabase вместо твърдо зададения списък. `librarian.js` чете същата база.
4. SQL структурата `schema.sql` описва `genres`, `books`, `copies` с PK/FK и примерни записи.
5. Приложена е защитена SQL миграция от `docs/STAGE_2_MIGRATION.sql` с RLS политики и `add_book_with_copy`, позволяваща запис само за удостоверен библиотекар.
6. Добавени са адаптивни CSS стилове, документация в README и конкретната ER диаграма `docs/ER_STAGE_2.md`.

## 3. База данни и проверка

Проверка чрез свързания Supabase проект на 16.11.2026:

| Таблица | Начален брой | Връзка |
|---|---:|---|
| genres | 4 | PK id |
| books | 6 | FK genre_id → genres.id |
| copies | 11 | FK book_id → books.id |

RLS е включен за трите таблици. Проверка на правата за функцията установи, че `anon` няма EXECUTE, а `authenticated` има EXECUTE; политиките допълнително изискват библиотекарска роля за INSERT. Supabase security advisors не върнаха предупреждения при проверката.

**Важно:** функцията за запис е създадена, но успешен вход и INSERT през браузъра все още не са демонстрирани с действително конфигуриран библиотекарски профил. Администратор трябва да създаде/упълномощи такъв потребител чрез Supabase Auth, без да записва тайни ключове в кода.

## 5. Ограничения и следващи етапи

- Резервациите в `index.html` са **локално демо в localStorage**, не реални резервации в Supabase.
- Пълно управление на заемания, връщания и акаунти на ученици е предвидено за следващите етапи.
- Задължителни за учебната оценка са реални проверки на двата екрана и индивидуални GitHub приноси.

## 6. Какво беше трудно

- Началният JavaScript имаше функция за Supabase, но тя не се извикваше. Добавено е реалното зареждане, а статичният списък е премахнат.
- Публичен GitHub Pages сайт не може безопасно да използва secret/service_role ключове. Вместо публичен INSERT е добавена удостоверена форма и ограничени чрез RLS операции.
- Вторият библиотекарски екран е отделен HTML файл с общите CSS стилове.
